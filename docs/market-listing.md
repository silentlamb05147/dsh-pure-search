# 插件市场文案（dsh-kb-lite-local）

> 上架用文案草稿。市场卡片通常只取「一句话简介」，详情页可用「详细介绍」。

## 卡片

- **名称**：dsh-kb-lite-local
- **副标题**：本地知识库：六类文档、分层索引、文档内分段重排、原文出处
- **一句话简介**（≤ 60 字）：
  把 Markdown/TXT/PDF/Word/HTML/JSON 收进本地索引，按工作区与会话分层，查询带原文出处。
- **分类**：知识库 / 检索增强
- **关键词**：知识库、RAG、BM25、本地、离线、DOCX、PDF、分层索引、引用

## 详细介绍

**给 DeepSeek Harness 的离线知识库。**

把项目文档丢进本地索引，之后用一句话就能找回原文，并且拿到可以直接核对的出处：文件路径、标题、小标题、行号或页码。全程不联网、不调模型、不打开端口。

**支持六类文档。** Markdown 与纯文本按标题分块；PDF 用 PyMuPDF 抽文本、按页引用；Word 直接解析 `word/document.xml`，不依赖 Office；HTML 跳过脚本与样式，只留正文；JSON 递归扁平化成键值路径，方便查配置项。目录可递归入库，自动跳过 `.git`、`node_modules`、虚拟环境与缓存目录。

**按工作区、按会话分层。** 每个工作区有一层公共文档（`_shared`），每个会话还能有自己的一层。查询先看会话层，查不到再回退工作区层，两层分数不混算——换项目不会串档，会话里的临时资料也不会污染公共库。

**中文检索。** BM25 按二元组切词，换一种说法也能命中；可选接入本地向量模型（bge-small-zh）做混合检索，用 RRF 融合两路结果。所有结果都带出处，`kb_ask` 只返回原文，不改写、不摘要。

**实测水准。** 7 篇中文文档（259 KB、376 块）上，7 个自然语言问题 top-3 命中 7/7；索引在进程内缓存后，单次查询中位 5.3 ms（p95 10.6 ms），冷启动约 280 ms；建索引 8 篇 132 ms、37 篇 746 ms。对照逐字匹配脚本只命中 2/7。

**轻。** 宿主侧九个工具，另带一个只读设置页（列出已索引文件、可从索引移除）；引擎是单文件 Python，BM25 只用标准库，PDF 才需要 pymupdf，向量检索才需要额外依赖。默认完全离线。

**已知限制。** BM25 索引每次查询重建，语料越大越慢（2000 块约 200–400 ms）；扫描版 PDF 需先 OCR；DOCX 只取正文文本；JSON 扁平化深度上限 8 层；稠密检索默认关闭。
